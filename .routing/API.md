# API & Static Adapter Architecture (`API.md`)

> **Frontend API layer design, static mock adapter strategy, and Go backend synchronization.**  
> Central architectural reference for all agents when implementing or calling backend APIs in `app/frontend/src/api/`.

---

## 1. Motivation & Problems Solved

In the legacy implementation (`local-app/frontend/src/api/`), the frontend was tightly coupled to runtime Wails bindings. Running or exploring the frontend required booting the entire Vagrant VM, PostgreSQL instance, and Go backend services. When disconnected, views crashed or developers had to hardcode massive mock objects directly into Vue components. Furthermore, the contracts were machine-generated, and real-time WebSockets were conflated into HTTP RPC adapters.

The rebuilt architecture in `app/frontend/src/api/` introduces a **Pluggable Static Adapter Pattern**:
1. **Instant Offline Exploration:** The entire application can run and be fully explored offline using rich, realistic in-memory Spanish mock fixtures without running Vagrant, Docker, or PostgreSQL.
2. **Compile-Time Go Backend Synchronization:** Strong TypeScript interfaces that automatically enforce zero drift against Go backend models.
3. **Domain Segregation:** Granular, domain-scoped API clients (`api.auth`, `api.dictionary`, `api.studio`, `api.arena`) rather than an 800-line god-object.

## 3. The Three Pillars of Synchronization with Go

To guarantee that hand-crafted TypeScript contracts never drift from the Go backend implementation, the architecture enforces three compile-time pillars:

### Pillar 1: Models Imported Directly from Autogenerated Bindings
The contract interfaces in `contract/` **never redefine or duplicate DTO structures**. They import the DTO classes directly from `@bindings/palabrario/pkg/models`:

```ts
// app/frontend/src/api/contract/dictionary.contract.ts
import type {
  WordDetail,
  WordSearchResult,
  WordExploreFilter,
} from "@bindings/palabrario/pkg/models/index.js"

export interface IDictionaryAPI {
  getWordOfTheDay(dialect?: string): Promise<WordDetail | null>
  searchWords(query: string, dialect?: string, limit?: number): Promise<WordSearchResult[]>
  getWordById(id: number): Promise<WordDetail | null>
}
```
*Benefit:* When a Go struct in `pkg/models/` changes (e.g. adding a field), Wails updates `@bindings`. The change immediately propagates throughout the TypeScript layer.

### Pillar 2: WailsAdapter Acts as the Type Guard
`WailsAdapter` implements the contract interface by delegating directly to the Wails bridge methods:

```ts
// app/frontend/src/api/live/wails/dictionary.wails.ts
import type { IDictionaryAPI } from "@/api/contract/dictionary.contract"
import * as Wails from "@bindings/palabrario/app/app.js"

export class WailsDictionaryAdapter implements IDictionaryAPI {
  async searchWords(query: string, dialect = "", limit = 20) {
    // If the Go signature changes in app_dictionary.go,
    // TypeScript will error right here during `vue-tsc --noEmit`!
    return await Wails.SearchWords(query, dialect, limit)
  }

  async getWordById(id: number) {
    return await Wails.GetWordDetail(id)
  }
}
```
*Benefit:* Any modification to a Go method signature changes the autogenerated `Wails.*` export, causing `WailsDictionaryAdapter` to immediately fail TypeScript type-checking if the contract is out of sync.

### Pillar 3: Automated Enforcement in `wails3 task check`
The project's Taskfile pipeline runs on every check and build:
```
wails3 task check
  ├── 1. wails3 generate bindings (regenerates @bindings directly from Go AST)
  ├── 2. bun run type-check (`vue-tsc --noEmit` checks TS against fresh bindings)
  ├── 3. bun run build (Vite production build)
  └── 4. go build . (compiles Go binary)
```
No ticket can be accepted unless `wails3 task check` exits with code `0`. Drift cannot pass this gate.

## 4. Static Mock & Offline Exploration

### How Runtime Switching Works (`index.ts`)
The active API adapter is resolved once at application startup using a clear precedence hierarchy:

```ts
// app/frontend/src/api/index.ts
export type APIMode = "auto" | "wails" | "http" | "mock"

function resolveAPIMode(): APIMode {
  // 1. Manual developer override in localStorage
  const saved = localStorage.getItem("palabrario_api_mode") as APIMode | null
  if (saved && ["wails", "http", "mock"].includes(saved)) {
    return saved
  }
  // 2. Build-time Vite environment variable
  const envMode = import.meta.env.VITE_API_MODE as APIMode | undefined
  if (envMode && ["wails", "http", "mock"].includes(envMode)) {
    return envMode
  }
  return "auto"
}
```

### Enabling Mock Mode
- **Via Browser Console / DevTools:**
  ```js
  localStorage.setItem('palabrario_api_mode', 'mock')
  location.reload()
  ```
- **Via Vite Environment Variable:**
  ```env
  VITE_API_MODE=mock
  ```
- **To Return to Auto (Live Backend):**
  ```js
  localStorage.removeItem('palabrario_api_mode')
  location.reload()
  ```

### Mock Fixtures Rules
1. **Pure Spanish Content:** All mock linguistic data (lemmas, senses, blurbs, examples, cultural notes, etymologies, deck titles) must be in authentic Spanish. UI chrome labels remain in English.
2. **Zero Flags / Zero Regional Codes:** Region names inside mock data must always be full text names (`Cuba`, `Chile`, `Mexico`, `Spain`, `Argentina`). Never render flag emojis or dialect abbreviations (`CU`, `CL`).
3. **In-Memory Statefulness:** `MockAdapter` maintains simple in-memory collections and `localStorage` flags (e.g. `mock_logged_in: true`) so flows like Sign In $\to$ View Profile $\to$ Add Deck Item $\to$ Sign Out persist during a session.
4. **Realistic Latency:** Async methods in `MockAdapter` simulate a realistic network/IPC delay (50–150ms) to ensure UI loading spinners and skeletons trigger as they would in production.

## 5. Rules for Frontend Agents & Developers

1. **Never Import `@bindings` in UI Components:**  
   Vue components and views (`*.vue`, stores, composables) must **never** import Wails bindings directly (`import * as Wails from "@bindings/palabrario/app/app"`). Always import the domain client from `@/api`:
   ```ts
   // CORRECT:
   import { api } from "@/api"
   const results = await api.dictionary.searchWords(query.value)

   // FORBIDDEN:
   import { SearchWords } from "@bindings/palabrario/app/app"
   ```
2. **Never Return Wails `$CancellablePromise<T>` in Contracts:**  
   Contract interfaces must always return standard native `Promise<T>`. Proprietary Wails promises are unwrapped inside `wails.adapter.ts`.
3. **Modular Domain Expansion:**  
   When a new route requires API methods (e.g. Arena in Ticket 017), add the contract method to `contract/`, implement it in `live/wails/`, and implement a realistic mock response in `mock/`.

## 6. Auth Contract & Session Lifecycle (`IAuthAPI`)

Token storage and refresh rotation are encapsulated inside each transport adapter (Go RAM + disk refresh token for `WailsAuthAdapter`; `localStorage` for `MockAuthAPI`; `@capacitor/preferences` for the future `http` adapter). The frontend contract never exposes `AuthResponse` or `hasActiveSession()`:

```ts
// app/frontend/src/api/contract/auth.contract.ts
export interface IAuthAPI {
  signIn(req: SignInRequest): Promise<UserProfile>
  signUp(req: SignUpRequest): Promise<UserProfile>
  signOut(): Promise<void>
  getMe(): Promise<UserProfile | null>
  getPublicProfileByUsername(username: string): Promise<PublicUserProfile | null>
  onSessionExpired(callback: (reason: string) => void): () => void
}
```

### Contract Guarantees
1. **`signIn` / `signUp`:** Always resolve with `UserProfile` on success or reject with a normalized `Error` (e.g., invalid credentials, suspended account, duplicate email/username, validation error). Never return `null`.
2. **`getMe`:** Hydrates the active session in a single round-trip. Returns `null` when unauthenticated or when an expired/suspended session is cleared.
3. **`getPublicProfileByUsername`:** Returns `null` when the user does not exist or is inactive (`is_active = false`); throws on network/server failures so views can distinguish `404` from retryable errors.
4. **`onSessionExpired`:** Subscribes to out-of-band session eviction events (in Wails, `"auth:expired"` emitted by `App` on unrecoverable `401` or `403 ACCOUNT_SUSPENDED`). `useAuth()` registers this listener once on initialization to clear `currentUser`, populate `sessionNotice`, and trigger a redirect to `/auth/sign-in` when on a `meta.requiresAuth` route.
